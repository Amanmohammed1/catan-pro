# M1 — Base game rules, complete

**Status:** complete

**Goal:** a correct, fully playable base game, hot-seat, in the 2D renderer.

## Acceptance criteria

| Criterion                                                     | Result                                   |
| ------------------------------------------------------------- | ---------------------------------------- |
| `pnpm fuzz` passes 10,000 self-play games                     | clean, 10.19M actions                    |
| No crash, negative resources, bank overdraft or infinite game | invariants checked after every action    |
| A full hot-seat game is playable in the 2D renderer           | driven end to end in `GameView.test.tsx` |
| Longest road suite of at least 30 cases                       | 52 cases                                 |
| Rulebook cited for anything easy to get wrong                 | page references throughout               |

## Rules implemented

Every rule below carries a page citation to `docs/rules/` in the code.

- **Setup (p.12).** Two rounds, seat order then reversed, settlement followed by
  an adjoining road. The second settlement pays out its adjacent hexes. The
  starting player places last and plays first.
- **Production (p.4, p.10).** One card per settlement, two per city. The robber
  suppresses its hex. The bank shortage rule is implemented in full, including
  the exception where a single affected player takes what is left.
- **The 7 (p.5, p.11).** Discard half rounded down above seven cards, then the
  roller moves the robber to a _different_ hex, then steals from an adjacent
  opponent who actually holds a card.
- **Building (p.4-5).** Costs, the distance rule, road connectivity including
  the blocking rule from Illustration K, city upgrades returning the settlement
  piece to stock, and the 15/5/4 piece limits.
- **Development cards (p.5, p.7, p.8, p.10).** The 25-card deck in its published
  mix. One card per turn, never one bought the same turn, playable before the
  roll. Knight, Road Building, Year of Plenty, Monopoly, and hidden victory
  point cards that can win on the turn they are bought.
- **Longest Road (p.4, p.9).** Longest edge-distinct run, blocked by an
  opponent's building at an intermediate intersection, with the almanac's
  tie-breaking rules in full — the holder keeps the card while tied, and the
  card is set aside when the holder falls behind a multi-way tie.
- **Largest Army (p.8).** Three knights to claim, strictly more to take.
- **Trade (p.4, p.7, p.9).** Maritime at 4:1, 3:1 and 2:1 with harbours, and
  domestic offers with accept, decline, confirm and cancel.
- **Winning (p.7).** Only on your own turn.

## Two bugs worth recording

**The purity guard was enforcing nothing.** Not an M1 bug, but found here: the
boundary policies used a `file.categories.noneOf` selector to exempt tests, and
that selector matches nothing when a file has no category at all. Lint passed on
an engine file importing `node:fs`. Fixed, and `scripts/verify-boundary-fires.mjs`
now fails the build if the guard ever stops reporting.

**Road Building before the roll swallowed the dice.** The card is legal before
rolling (p.7), but the phase returned to `main` when the free roads were placed,
skipping the player's roll and everyone's production for that turn. The fuzzer
could not catch it: nothing about it breaks an invariant, and the game continues
legally. The phase now records where to return, the same way the robber does.
Found by reading the phase machine, not by testing, which is a good argument for
doing both.

## Structure

```
packages/engine/src/
  state/        GameState, resource arithmetic, invariants
  actions/      the Action union
  events/       the Event union
  phases/       the explicit phase machine
  setup/        createGame
  queries/      legalMoves, longestRoad, scores, placement, playerView
  reducers/     reduce, production, special cards
apps/bot-runner/  random-legal self-play, `pnpm fuzz`
apps/web/src/game/  hot-seat UI
```

## Commands

```bash
pnpm verify                      # lint, typecheck, purity guards, 327 tests
pnpm fuzz                        # 10,000 self-play games
pnpm fuzz --games 500 --players 3
pnpm dev                         # play at http://localhost:5173
pnpm dev                         # ?debug=1 for the M0 geometry view
```

## Known gaps, deliberately left for later

- `offerTrade` is validated rather than enumerated. See ADR 0003.
- The fuzzer therefore never proposes a domestic trade; the trade tests cover
  that path instead.
- No server, no persistence, no redaction over the wire. `playerView()` exists
  and is tested, but nothing transmits yet. That is M2.
- Random-legal games average ~320 turns, far longer than a real game. That is a
  property of the bot, not the rules; heuristic bots are M9.
