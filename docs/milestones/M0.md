# M0 — Skeleton and geometry

**Status:** complete

**Goal:** a board graph you can look at.

## Acceptance criteria

| Criterion                                         | Result                                |
| ------------------------------------------------- | ------------------------------------- |
| Classic board builds 19 tiles, 54 nodes, 72 edges | met                                   |
| Every edge has exactly 2 nodes                    | met                                   |
| Adjacency is symmetric in every direction         | met                                   |
| Same seed produces an identical board             | met, asserted byte-for-byte           |
| Engine imports nothing                            | met, enforced by lint and two scripts |
| SVG debug renderer draws the graph                | met                                   |

One stated criterion was wrong and is recorded below.

### "Every node has 2-3 adjacent tiles" is false

A bare 19-tile board has no surrounding sea frame, so its rim nodes touch fewer
than two tiles. The real distribution, computed twice by independent code:

| Adjacent tiles | Nodes |
| -------------- | ----- |
| 1              | 18    |
| 2              | 12    |
| 3              | 24    |

The 18 single-tile nodes are the outer points of the coastline. This is correct
and expected for a frameless board. Adding the Seafarers sea ring in M6 turns all
54 of these into three-cell nodes. The test asserts the exact distribution rather
than a range, which is a stronger guard than the original wording would have been.

## What exists

```
packages/engine/      pure: coordinates, identity, board graph, seeded PRNG
packages/scenarios/   zod schema, classic board data, two test fixtures
apps/web/             the ugly 2D SVG debug renderer
scripts/              data generators and the two purity guards
docs/adr/             0001 vertex identity, 0002 TypeScript pin
```

The engine has zero runtime dependencies and its tsconfig excludes the DOM and
Node type libraries, so it cannot reference a browser or Node global even by
accident.

## Commands

```bash
pnpm install
pnpm verify      # lint, typecheck, both purity guards, tests
pnpm dev         # the debug renderer at http://localhost:5173
pnpm test        # 142 tests
```

`pnpm dev` accepts `?seed=` and `?scenario=` query parameters. The same seed
always yields the same board.

## Notes for M1

- `buildBoardGraph` returns `{ board, rng }`. Thread the returned PRNG state into
  `GameState` rather than reseeding, or replays will diverge.
- Edges already carry `kind` of `land`, `sea` or `coast`, computed from cell
  slots. The classic board is entirely land edges. Seafarers ships in M6 will use
  `coast` and `sea` without a geometry change.
- The scenario format already carries `islands`, `hiddenStacks`, `startingPieces`,
  a `ships` piece count and a `gold` terrain. All are unused until M5 to M7.
- The red-number constraint is enforced by reshuffling, and throws a clear error
  when the constraint is unsatisfiable rather than looping. A radius-1 board
  cannot hold four red numbers, and the test suite pins that behaviour.

## Deliberately not done

No `GameState`, `Action`, `Event`, reducers, phases, `legalMoves` or rule modules.
No server, persistence or 3D. Those are M1 onward.
